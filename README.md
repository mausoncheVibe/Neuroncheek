# NEURONCHIK 1.0

Один Telegram user account → один разрешённый собеседник → DeepSeek.
Python 3.10+. Только личный текст и подписи к медиа. Участник заранее согласен
на эксперимент с ИИ. Все ответы автономные; инициатива изначально выключена.

## Запуск за три действия

1. Распакуй архив. Положи **готовую авторизованную Telethon `.session`** рядом
   с `neuron.py`. Не запускай другой скрипт с этой же сессией одновременно.
   Сессии Pyrogram и строки StringSession не подходят. Скрипт не запрашивает
   телефон, код или пароль и не создаёт новую авторизацию.
2. Заполни `secrets.env` и поставь **положительный числовой ID собеседника** в
   `settings.json` → `allowed_user_id`. Сейчас там `0`: запуск намеренно запрещён.
   Username, телефон, ID группы, свой ID и `all` не подходят.
3. В папке проекта выполни:

   ```sh
   python -m pip install -r requirements.txt
   python neuron.py
   ```

Остановка: **Ctrl+C**. Для первого ответа собеседник должен отправить новое
сообщение после строки `started`. Старые сообщения при старте не обрабатываются.

## Android / Termux

Работай в домашней папке Termux, чтобы SQLite-сессия находилась в обычной
файловой системе, а не в общем Android-хранилище.

```sh
pkg update && pkg install python unzip -y
termux-setup-storage
mkdir -p ~/projects
unzip ~/storage/downloads/NEURONCHIK_1_0.zip -d ~/projects
cd ~/projects/NEURONCHIK_1_0
python -m pip install -r requirements.txt
python neuron.py
```

Между распаковкой и запуском создай локальный `secrets.env` командой `cp secrets.env.example secrets.env`, перенеси `.session` и заполни два файла настроек.
`termux-setup-storage` запрашивает доступ к файлам Android. Если загрузка
переименовала ZIP, подставь его фактическое имя в команду `unzip`.

Если установка `jiter` / `pydantic-core` требует компилятора:

```sh
pkg install rust clang make pkg-config -y
python -m pip install -r requirements.txt
```

При необходимости удерживать процесс с выключенным экраном используй
`termux-wake-lock` и разреши Termux фоновую работу в настройках Android.
После остановки — `termux-wake-unlock`. Android всё равно может завершить
приложение. Установка и фоновая работа на реальном Termux здесь не проверялись.

Linux / Windows: открой терминал в распакованной папке и используй две команды
из «Запуск за три действия». На Windows команда Python может называться `py`.

## Три редактируемых файла

| Файл | Что менять |
| --- | --- |
| `persona.txt` | Характер, манеру речи, интересы и вымышленную биографию. Перечитывается перед каждым запросом. |
| `secrets.env.example` | Безопасный шаблон. Скопируй в `secrets.env` (только локально) для Telegram API ID/HASH, пути к сессии и ключа DeepSeek. |
| `settings.json` | Единственный разрешённый ID, флаги, задержки и лимиты. |

Пример `secrets.env.example` — скопируй его локально в `secrets.env` и впиши свои значения без угловых скобок:

```dotenv
TELEGRAM_API_ID=123456
TELEGRAM_API_HASH=ВСТАВЬ_СВОЙ_32_СИМВОЛЬНЫЙ_HASH
TELEGRAM_SESSION_PATH=account.session
DEEPSEEK_API_KEY=ВСТАВЬ_СВОЙ_КЛЮЧ
```

Telegram API ID/HASH: [my.telegram.org](https://my.telegram.org) → API development
tools. Это данные Telegram-приложения, а не bot token.
DeepSeek API key и положительный баланс: [platform.deepseek.com](https://platform.deepseek.com).
Путь к сессии считается от папки проекта; абсолютный путь тоже работает.
Для `account` используется `account.session`; двойной суффикс не добавляется.
Если ID ещё не встречался в кэше сессии, скрипт остановится с ошибкой разрешения
цели: открой уже существующий личный диалог клиентом, использующим эту сессию.

`DEEPSEEK_BASE_URL` необязателен; по умолчанию `https://api.deepseek.com`.
Изменённый endpoint получает ключ и контекст переписки: меняй его только осознанно.
Секреты, сессию и её служебные файлы не отправляй в чаты и репозитории.
В репозитории лежит только пустой шаблон `secrets.env.example`. Скопируй его в локальный `secrets.env` и заполни секретами; настоящий файл и `.session` не загружай на GitHub.

## Настройки

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `enabled` | `true` | `false`: чистый выход без подключения и отправки. |
| `allowed_user_id` | `0` | Обязательно заменить на один положительный integer. |
| `initiate_first` | `false` | Разрешает ограниченную инициативу. |
| `model` | `deepseek-flash` | Модель DeepSeek; thinking явно выключен кодом. |
| `history_messages` | `30` | Последние 1–100 сообщений только этого диалога. |
| `debounce_seconds` | `5` | Окно тишины для объединения входящих. |
| `reply_delay_seconds` | `3` | Дополнительная пауза перед генерацией. |
| `show_typing` | `true` | Индикатор «печатает» во время паузы и запроса. |
| `max_output_tokens` | `220` | Лимит ответа модели, 1–2048 токенов. |
| `initiative_after_hours` | `8` | Минимальная тишина после любой активности и старта. |
| `max_proactive_per_day` | `2` | Суточный лимит инициативы; сутки считаются в UTC. |
| `api_timeout_seconds` | `30` | Сетевой timeout SDK на операцию запроса. |

JSON не поддерживает комментарии. Флаги — `true`/`false`, ID — число без кавычек.
После изменения `settings.json` или `secrets.env` перезапусти программу.
`persona.txt` применяется к следующему запросу; уже выполняющийся использует
прочитанную версию. Чтобы выключить работающий процесс, нажми Ctrl+C:
редактирование `enabled` без перезапуска его не останавливает.

При смене ID/аккаунта останови процесс и сохрани старый `state.json` отдельно:
состояние привязано к паре аккаунт/собеседник. Для нового диалога оно создастся
автоматически. В обычной работе **не удаляй state.json**, чтобы сохранить блокировку
повторной инициативы. Не заменяй `secrets.env` во время работы: на нём стоит
блокировка второго экземпляра в этой папке.

## Поведение и границы

- Группы, каналы, другие ЛС, «Избранное» и собственные входящие отсекаются до API.
  История дополнительно проверяется по чату и отправителю. Медиа не скачиваются;
  непустая текстовая подпись учитывается. Текст и история разрешённого диалога
  передаются DeepSeek. В `state.json` переписка и ключи не сохраняются.
- Пачка близких сообщений получает один ответ. Новое входящее во время генерации
  отменяет устаревший ответ: после тишины контекст собирается заново. Такой
  отброшенный запрос уже мог потратить токены. Ручное исходящее владельца в этом
  диалоге сбрасывает тишину и подавляет ожидающий автоответ.
- Инициатива разрешена только после существующего входящего диалога и полного
  интервала тишины после запуска. После одного сообщения программа ждёт нового
  входящего, даже через несколько суток и перезапусков. Пустая доступная история
  запрещает инициативу. Проверка — раз в минуту. Тихие часы не реализованы.
- Состояние записывается атомарно. Повреждённый или чужой `state.json` останавливает
  запуск. После рестарта накопленный backlog пропускается. Обрабатываются новые
  события; доставки каждого сообщения при сбоях не гарантируется.
- Перед отправкой пачка отмечается обработанной, а инициатива резервируется.
  При аварии или сетевом разрыве ответ может потеряться; отправка Telegram
  автоматически не повторяется, чтобы не создавать дубли при неизвестном
  результате. Это **не exactly-once**. Новое входящее позволяет продолжить диалог.
  Ручное сообщение, пришедшее уже во время сетевой отправки, не может отозвать её.
- Временный сбой API повторяется не более одного раза; timeout применяется к
  сетевой операции SDK, а не ко всему ответу с паузами и повтором. Инициатива
  после ошибки откладывается ещё на полный интервал тишины.
- Один экземпляр в одной папке. Не используй копии одной сессии одновременно в
  разных папках/процессах. Скрипт требует права записи рядом с собой и в `secrets.env`.
- Только текст, один аккаунт и один собеседник: голос, vision, отправка медиа,
  веб-панель, рассылки и интеграция с UZBEKI отсутствуют.

## Краткие ошибки

| Лог | Действие |
| --- | --- |
| `authorized as ID` / `target resolved` / `started` | Аккаунт прочитан, цель найдена, слушатель включён. |
| `message handled` | Telegram принял отправку обычного ответа. |
| `API error HTTP 401/402/403/404` | Проверь ключ / баланс / доступ / модель, затем перезапусти. API до рестарта приостановлен. |
| `API error HTTP 429` | Ограниченный повтор; долгий Retry-After откладывает следующие запросы, без шторма. |
| `API empty/refused response` | Ничего не отправлено; ожидается новое входящее. |
| `Telegram FloodWait` | Дождись указанного интервала. Пропущенная пачка автоматически не повторяется. |
| `Telegram/network error` | Проверь сеть и сессию; отправка с неизвестным результатом не повторяется. |
| `state.json` / `Ошибка обработчика` | Проверь файл, права записи и свободное место; исправь причину и перезапусти. |
| `Unexpected failure` | Процесс остановлен. Проверь конфиги и зависимости, выполни тесты ниже. |

По умолчанию лог не содержит текстов переписки, ключей и содержимого сессии.
Исключение из минимальных метаданных: при авторизации печатается ID своего аккаунта.

## Проверка

```sh
python -m py_compile neuron.py
python -m unittest discover -s tests -v
```

**45 offline-тестов прошли** в чистом Linux venv / Python 3.12.14:
Telethon 1.45.0, openai 2.54.0, python-dotenv 1.2.4. Проверены фильтры, debounce,
гонки, история, инициатива/рестарты, атомарность состояния, ошибки, закрытие
соединений, полная связка обработчиков и реальная сериализация OpenAI SDK через
mock HTTP transport. Настоящие Telegram/DeepSeek-запросы, Termux и Windows
не проверялись; для live-проверки нужны свои ключи, баланс, сессия, ID и согласие.
